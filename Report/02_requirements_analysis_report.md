# 02. 요구사항 분석 보고서

## 개요

- 대상 프로젝트: TDD TV C++17 프로젝트
- 작성 파일: `docs/requirements_analysis.md`
- 목적: `README.md` 요구사항을 C++ 구현과 Google Test 검증 관점으로 재정리
- 작성일: 2026-05-19

## 분석 범위

`README.md`에 정의된 리모컨 입력, 채널 범위, 튜너 API, 선호 채널, 채널 검색, 업/다운 동작을 기준으로 요구사항을 정리했다. 구현 코드 관점에서는 `TVController`, `Tuner`, `remoteKey`의 현재 인터페이스와 기존 `TunerTest.cpp`, `TVControllerTest.cpp`의 Google Test/Mock 사용 방식을 함께 확인했다.

## 주요 산출 내용

### 모듈별 비즈니스 규칙

- 리모컨/TVController는 숫자 입력 버퍼, 채널 확정, 채널 업/다운, 채널 검색, 선호 채널 추가/이동 규칙을 담당한다.
- Tuner는 외부 업체 제공 의존성으로 보고 `seekCH()`, `setCH()`, `getCurrentCH()` 호출 계약을 중심으로 정리했다.
- Controller 테스트에서는 Tuner 구현 자체보다 Mock/Fake를 사용한 연동 계약 검증이 중요하다.

### 리모컨 입력 주의점

- 숫자 버튼 입력은 즉시 채널 변경이 아니라 입력 버퍼 상태를 가진다.
- 두 자리 입력은 자동 확정하고, 한 자리 입력은 `OK` 또는 다음 숫자 입력에 따라 확정해야 한다.
- `4`, `5`, `6`처럼 홀수 개 숫자가 들어오는 경우 확정된 채널과 대기 중인 숫자 버퍼를 분리해야 한다.
- 숫자 버퍼가 남아 있을 때 숫자/`OK` 외 버튼이 입력되면 해당 버퍼를 무효화해야 한다.

### 예외 및 경계값

- 일반 채널의 유효 범위는 0부터 99까지이다.
- 99에서 채널 업은 0, 0에서 채널 다운은 99로 순환한다.
- 검색 결과가 있는 경우 업/다운은 전체 채널이 아니라 저장된 검색 채널 목록 안에서 이동한다.
- 선호 채널 목록이 비어 있거나 하나만 있는 경우의 동작도 테스트 기준으로 명확히 해야 한다.
- Tuner가 예외를 던질 수 있는 범위 밖 채널과 비정상 문자열 반환에 대한 처리 정책을 별도로 결정해야 한다.

### Google Test 시나리오

- Tuner API 계약 검증 시나리오를 포함했다.
- 숫자 입력, `OK`, 연속 숫자, 앞자리 0, 채널 업/다운, 검색 결과 기반 이동, 선호 채널 toggle, 다음 선호 채널 순환까지 총 22개 테스트 시나리오를 번호 목록으로 정리했다.
- 향후 `TVControllerTest.cpp` 작성 시 `EXPECT_CALL`, `InSequence`, `WillOnce`, `WillRepeatedly`를 사용해 동작 순서와 호출 인자를 검증할 수 있다.

## QA 관점 기대 효과

- 요구사항을 구현 단위와 테스트 단위로 나누어 TDD 시작점을 명확히 했다.
- 채널 0/99, 100 이상, 선호 채널 없음, 검색 결과 없음/있음 같은 경계 조건을 빠뜨리지 않도록 했다.
- 외부 의존성인 Tuner를 직접 검증 대상이 아니라 Controller의 협력 객체로 다루는 테스트 전략을 정리했다.
- 이후 리팩토링이나 기능 확장 시 회귀 테스트 목록의 기준 문서로 사용할 수 있다.

# 01. Cursor Rules 작성 보고서

## 개요

- 대상 프로젝트: TDD TV C++17 프로젝트
- 작성 파일: `.cursorrules`
- 목적: Cursor AI가 프로젝트 작업 시 지켜야 할 QA, 테스트, 리팩토링, Git 규칙을 명문화
- 작성일: 2026-05-19

## 반영 배경

`README.md` 기준으로 이 프로젝트는 리모컨 입력을 받아 TV 채널을 제어하는 Controller 모듈을 TDD 방식으로 개발하는 실습 프로젝트이다. 일반 채널 범위는 0부터 99까지이며, `Tuner`는 외부 업체가 제공하는 의존성으로 간주한다.

따라서 Cursor AI가 작업할 때 도메인 불변식을 훼손하지 않고, 테스트 우선 개발과 안전한 리팩토링 원칙을 따르도록 `.cursorrules` 파일을 작성했다.

## 주요 규칙

### 기술 스택

- C++17 사용
- CMake 기반 빌드
- Google Test 기반 단위 테스트
- lcov 기반 커버리지 확인

### 도메인 규칙

- 유효한 TV 채널은 0부터 99까지이다.
- 채널 99에서 채널 업을 하면 0으로 순환한다.
- 채널 0에서 채널 다운을 하면 99로 순환한다.
- `Tuner`는 외부 의존성으로 보고 Fake 또는 Mock을 사용해 Controller 로직을 검증한다.

### 테스트 규칙

- 테스트는 Given-When-Then 구조가 드러나도록 작성한다.
- 테스트 메서드명은 `should_[result]_when_[condition]` 형식을 따른다.
- 공통 Fixture가 필요한 경우 `TEST_F`를 우선 사용한다.
- 채널 변경이나 검증 로직을 수정할 때는 채널 0과 99 경계값 테스트를 포함한다.

### 코드 및 리팩토링 규칙

- 한 함수는 최대 20줄 이하로 유지한다.
- 리팩토링은 테스트가 Green인 상태에서만 진행한다.
- 매직 넘버는 가능하면 의미 있는 상수로 대체한다.
- 리팩토링은 동작 보존을 기본 원칙으로 한다.

### Git 규칙

- `git merge`를 실행하지 않는다.
- 사용자가 명시적으로 요청하지 않은 commit, push, rebase, reset, checkout은 수행하지 않는다.
- 사용자의 기존 변경사항을 임의로 되돌리지 않는다.

## 기대 효과

- Cursor AI가 프로젝트의 채널 범위와 래핑 규칙을 일관되게 유지한다.
- 테스트 이름, 테스트 구조, 경계값 테스트 기준이 명확해진다.
- 리팩토링 시 테스트 Green 상태와 함수 크기 제한을 기준으로 작은 변경을 유도한다.
- Git 작업 중 의도하지 않은 merge나 사용자 변경 손실을 방지한다.

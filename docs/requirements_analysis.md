# TDD TV 요구사항 분석

## 1. 모듈별 비즈니스 규칙

### 리모컨 / TVController

| 구분 | 입력 / 상태 | 비즈니스 규칙 | C++ 구현 관점 |
|---|---|---|---|
| 숫자 입력 | `0`~`9` | 숫자 버튼으로 채널 번호를 입력한다. | 입력 중인 숫자를 버퍼로 관리하고, 최대 2자리 채널로 확정한다. |
| 한 자리 확정 | `1` + `OK` | 1번 채널로 변경한다. | `OK` 입력 시 버퍼의 값을 정수/문자열 채널로 변환해 `Tuner::setCH()`를 호출한다. |
| 두 자리 자동 확정 | `1`, `2` | 12번 채널로 변경한다. | 숫자 버퍼가 2자리가 되면 즉시 채널을 확정하고 버퍼를 비운다. |
| 연속 숫자 입력 | `1`, `2`, `3`, `4` | 12번으로 변경 후 34번으로 변경한다. | 2자리 단위로 채널을 확정한다. |
| 남은 한 자리 입력 | `4`, `5`, `6` | 45번으로 변경 후 `6`은 대기 상태가 된다. 이후 숫자 또는 `OK` 입력으로 6번 계열을 확정할 수 있다. | 45 확정 후 남은 `6`은 버퍼에 유지한다. 다음 입력이 숫자/`OK`가 아니면 버퍼를 무효화한다. |
| 앞자리 0 | `0`, `7` | 7번 채널로 변경한다. | `"07"`은 유효 채널 7로 정규화한다. 표시/저장 형식은 프로젝트 기준으로 일관되게 결정한다. |
| 채널 업/다운 | 검색 결과 없음 | 현재 채널 기준으로 +1/-1 이동한다. 99 다음은 0, 0 이전은 99이다. | 현재 채널은 `Tuner::getCurrentCH()`로 조회하고 modulo 연산으로 순환 처리한다. |
| 채널 업/다운 | 검색 결과 있음 | 저장된 검색 채널 목록 안에서 다음/이전 채널로 이동한다. | 검색 결과를 정렬/중복 제거된 컬렉션으로 관리하면 다음/이전 탐색과 순환 처리가 단순해진다. |
| 채널 검색 | `KEY_SEARCH` | 모든 채널을 검색하여 저장한다. | `Tuner::seekCH()` 반복 호출 결과를 저장한다. 종료 조건과 중복 채널 처리 정책이 필요하다. |
| 선호 채널 추가 | `KEY_FAVORITE_ADD` | 현재 채널이 선호 채널이 아니면 추가하고, 이미 선호 채널이면 삭제한다. | `std::set<int>` 같은 자료구조로 toggle 동작을 구현한다. |
| 다음 선호 채널 | `KEY_FAVORITE_NEXT` | 현재 채널보다 큰 선호 채널 중 가장 작은 값으로 이동한다. 없으면 가장 작은 선호 채널로 순환한다. | `upper_bound()` 기반 탐색이 적합하다. 선호 채널이 비어 있을 때의 동작을 명확히 해야 한다. |

### 튜너

| 구분 | API | 비즈니스 규칙 | C++ 구현 관점 |
|---|---|---|---|
| 현재 채널 조회 | `getCurrentCH()` | 현재 튜너에 설정된 채널 값을 반환한다. | 외부 제공 모듈로 간주하고 Controller 테스트에서는 Mock/Fake로 대체한다. |
| 채널 설정 | `setCH(ch)` | 지정 채널로 현재 채널을 변경한다. | Controller는 유효 채널만 전달해야 하며, 테스트에서는 호출 인자와 호출 횟수를 검증한다. |
| 채널 검색 | `seekCH()` | 현재 채널에서 증가 방향으로 시청 가능한 채널을 검색하고, 검색된 채널로 변경한 뒤 반환한다. | 검색 버튼 테스트에서는 `EXPECT_CALL`과 `WillOnce`/`WillRepeatedly`로 반환 시퀀스를 제어한다. |
| 유효 범위 | `0`~`99` | 일반 채널은 0부터 99까지이다. | 범위 밖 값은 Controller에서 차단하거나 Tuner 예외를 전파/처리하는 정책을 정해야 한다. |
| 테스트 책임 | 전체 API | Tuner 자체의 정확한 동작은 업체 제공으로 가정한다. | Tuner 단위 구현 테스트보다 Controller와 Tuner 연동 계약 검증에 집중한다. |

## 2. 리모컨 버튼 입력 시 주의점

1. 숫자 입력은 즉시 채널 변경이 아니라 "입력 버퍼" 상태를 가진다. 2자리가 되거나 `OK`가 눌릴 때 채널을 확정해야 한다.
2. 2자리 채널이 확정된 뒤에도 다음 숫자가 이어질 수 있으므로, 버퍼 초기화 시점이 테스트 결과를 좌우한다.
3. `4`, `5`, `6`처럼 홀수 개 숫자가 들어오면 `45`는 확정되고 `6`은 다음 입력을 기다리는 상태로 남아야 한다.
4. 대기 중인 한 자리 숫자 뒤에 숫자 또는 `OK`가 아닌 버튼이 들어오면, 해당 숫자는 무효화해야 한다.
5. `0`, `7` 입력은 채널 7로 확정되어야 하며, `"07"`을 그대로 Tuner에 전달할지 `"7"`로 정규화할지 구현 규칙을 고정해야 한다.
6. 채널 업/다운은 검색 결과 저장 여부에 따라 완전히 다른 규칙을 사용한다.
7. 검색 결과 기반 업/다운에서는 현재 채널이 검색 목록에 없어도 다음/이전 검색 채널로 이동해야 한다.
8. 선호 채널 기능은 현재 채널 기준으로 동작하므로, 버튼 처리 직전에 `getCurrentCH()` 값을 신뢰 가능한 형태로 파싱해야 한다.
9. 어떤 버튼이든 채널 확정 또는 무효화 이후에는 입력 버퍼 상태를 명확히 정리해야 한다.

## 3. 예외 / 경계값 조건

| 조건 | 기대 동작 | 테스트 포인트 |
|---|---|---|
| 채널 최소값 | 0번 채널은 유효하다. | `setCH("0")`, `KEY_DOWN` 시 99로 순환 |
| 채널 최대값 | 99번 채널은 유효하다. | `setCH("99")`, `KEY_UP` 시 0으로 순환 |
| 음수 채널 | 유효하지 않다. | `-1`, `-12`, `-0` 입력 또는 전달 차단/예외 |
| 100 이상 채널 | 유효하지 않다. | `100`, `9999`는 `setCH()` 대상이 되지 않아야 함 |
| 두 자리 초과 숫자 입력 | 2자리 단위로 확정한다. | `1,2,3,4` -> 12, 34 |
| 앞자리 0 | 0으로 시작하는 두 자리 입력은 정규화한다. | `0,7` -> 7 |
| 검색 결과 없음 | 업/다운은 일반 채널 전체 범위에서 이동한다. | 6 -> 7/5, 99 -> 0, 0 -> 99 |
| 검색 결과 있음 | 업/다운은 저장된 채널 목록 안에서 순환한다. | 저장 채널 `4,6,14` 기준 6 -> 14/4, 15 -> 4/14 |
| 검색 결과 중복 | 중복 채널은 한 번만 저장하는 것이 자연스럽다. | `seekCH()`가 동일 채널을 반복 반환할 때 목록 중복 여부 |
| 검색 종료 | 모든 채널 검색 완료 조건이 필요하다. | 최대 100회 제한 또는 시작 채널 재방문 기준 |
| 선호 채널 없음 | 다음 선호 채널 이동 대상이 없다. | `setCH()` 호출 없음 또는 명시 예외 없음 정책 |
| 선호 채널 1개 | 다음 선호 채널은 자기 자신으로 순환할 수 있다. | 현재 채널과 동일한 선호 채널만 있을 때 동작 |
| 선호 채널 토글 | 이미 등록된 채널에서 추가 버튼을 누르면 삭제한다. | add 후 add 재입력 시 목록에서 제거 |
| Tuner 예외 | 범위 밖 채널 설정 시 `std::invalid_argument` 가능성이 있다. | Controller가 예외를 전파할지 내부 처리할지 결정 |
| 문자열 파싱 실패 | Tuner가 비숫자 문자열을 반환할 가능성 | Mock 기반 테스트에서 비정상 반환 처리 정책 확인 |

## 4. Google Test 기준 테스트 시나리오 목록

1. 초기 채널 조회 시 `getCurrentCH()`가 0~99 범위 값을 반환하는지 검증한다.
2. 유효 채널 `"0"`, `"4"`, `"5"`, `"12"`, `"99"`에 대해 `setCH()` 호출 계약을 검증한다.
3. 무효 채널 `"-12"`, `"-2"`, `"-0"`, `"100"`, `"9999"`에 대해 `std::invalid_argument` 예외 계약을 검증한다.
4. `seekCH()`를 반복 호출했을 때 반환 채널이 0~99 범위에 있는지 검증한다.
5. `KEY_1`, `KEY_OK` 입력 시 `setCH("1")`이 호출되는지 검증한다.
6. `KEY_1`, `KEY_2` 입력 시 `setCH("12")`가 호출되는지 검증한다.
7. `KEY_1`, `KEY_2`, `KEY_3`, `KEY_4` 입력 시 `setCH("12")`, `setCH("34")`가 순서대로 호출되는지 검증한다.
8. `KEY_4`, `KEY_5`, `KEY_6`, `KEY_OK` 입력 시 `setCH("45")`, `setCH("6")`이 순서대로 호출되는지 검증한다.
9. `KEY_4`, `KEY_5`, `KEY_6`, `KEY_UP` 입력 시 `6` 버퍼가 무효화되고 업 동작만 수행되는지 검증한다.
10. `KEY_0`, `KEY_7` 입력 시 `setCH("7")` 또는 합의된 정규화 형식으로 호출되는지 검증한다.
11. 검색 결과가 없고 현재 채널이 6일 때 `KEY_UP`은 7, `KEY_DOWN`은 5로 이동하는지 검증한다.
12. 검색 결과가 없고 현재 채널이 99일 때 `KEY_UP`은 0으로 순환하는지 검증한다.
13. 검색 결과가 없고 현재 채널이 0일 때 `KEY_DOWN`은 99로 순환하는지 검증한다.
14. 채널 검색 버튼 입력 시 `seekCH()`가 반복 호출되고 검색 결과가 저장되는지 검증한다.
15. 검색 결과가 `4, 6, 14`일 때 현재 채널 6에서 `KEY_UP`은 14, `KEY_DOWN`은 4로 이동하는지 검증한다.
16. 검색 결과가 `4, 6, 14`일 때 현재 채널 15에서 `KEY_UP`은 4, `KEY_DOWN`은 14로 순환하는지 검증한다.
17. 현재 채널이 선호 채널이 아닐 때 선호 채널 추가 버튼을 누르면 목록에 추가되는지 검증한다.
18. 현재 채널이 이미 선호 채널일 때 선호 채널 추가 버튼을 다시 누르면 목록에서 삭제되는지 검증한다.
19. 선호 채널이 `1, 4, 12, 56`이고 현재 채널이 6일 때 다음 선호 채널 버튼은 12로 이동하는지 검증한다.
20. 선호 채널이 `1, 4, 12, 56`이고 현재 채널이 56일 때 다음 선호 채널 버튼은 1로 순환하는지 검증한다.
21. 선호 채널 목록이 비어 있을 때 다음 선호 채널 버튼 입력이 `setCH()`를 호출하지 않는지 검증한다.
22. `Tuner` API는 Controller 테스트에서 `MockTuner` 또는 `FakeTuner`로 대체하고, Controller가 올바른 API를 올바른 순서와 인자로 호출하는지 검증한다.
